# Obsidian Hub 实施清单

> 当前阶段：规划完成，等待批准进入 M0  
> 本清单只覆盖已确认的 Windows 11 MVP。

## 使用规则

- 状态使用：`[ ]` 未开始、`[-]` 进行中、`[x]` 完成、`[!]` 阻塞。
- 每项完成必须同时满足代码、测试和验收条件。
- 任何新增范围先更新 `docs/plan/plan.md`，再进入本清单。
- 不为了“以后可能需要”提前实现 M4 之后的能力。

## M0：技术探针

目标：在正式搭建产品架构前，消除 Windows 与 Obsidian 集成风险。

- [ ] 检查本机 Node.js、pnpm、Rust、Cargo、MSVC Build Tools 和 WebView2 环境。
- [ ] 确认脚手架的稳定版本与锁定策略。
- [ ] 创建最小 Tauri 2 + React + TypeScript 探针。
- [ ] 验证 Windows 原生目录选择器。
- [ ] 验证 Rust 端目录存在性及 `.obsidian` 标记目录检查。
- [ ] 验证 `obsidian://open?vault=<name>` 的正确 URI 编码。
- [ ] 验证使用 Vault ID 打开仓库。
- [ ] 验证 Obsidian 未运行时的启动行为。
- [ ] 验证 Obsidian 已运行且当前为其他仓库时的行为。
- [ ] 验证目标仓库未注册或 URI handler 不存在时的行为。
- [ ] 确认 Tauri capability 可以只允许必要的目录与 `obsidian://` scheme。
- [ ] 记录探针结果并更新规划中的开放问题。

验收：关键系统行为有实机结论，技术方案不存在未说明的高风险假设。

## M1：端到端可用纵切

目标：完成“添加 -> 保存 -> 展示 -> 打开”的最小闭环。

### 项目基础

- [ ] 建立 pnpm、Vite、React、TypeScript 和 Tauri 2 工程。
- [ ] 配置格式化、Lint、类型检查、前端测试和 Rust 测试命令。
- [ ] 建立 `src/` 与 `src-tauri/src/` 的职责边界。
- [ ] 配置最小 Tauri capabilities。
- [ ] 增加统一错误 DTO 与前端错误映射。

### 数据层

- [ ] 定义 `VaultEntry`、`Preferences` 和 `AppConfigV1` 类型。
- [ ] 定义 `VaultRepository` 接口。
- [ ] 实现 AppData 配置文件读取。
- [ ] 实现配置默认值与 schema 校验。
- [ ] 实现临时文件加替换的原子写入。
- [ ] 增加损坏配置和不支持版本的错误处理。

### 仓库添加

- [ ] 实现系统目录选择。
- [ ] 实现 Windows 路径规范化。
- [ ] 校验目录存在且包含 `.obsidian`。
- [ ] 实现不区分大小写的重复路径检查。
- [ ] 用目录名预填展示名称。
- [ ] 完成最小添加仓库对话框。

### 仓库启动

- [ ] 定义 `VaultLauncher` 接口。
- [ ] 实现 Vault ID 优先、名称降级的 URI 构造。
- [ ] 对所有 URI 参数执行标准编码。
- [ ] 实现受限的系统 URI 调用。
- [ ] 仅在系统成功接收 URI 后更新 `lastOpenedAt`。
- [ ] 成功后按偏好关闭 Hub，失败时保留错误状态。

### 纵切验收

- [ ] 首次启动可添加一个真实仓库。
- [ ] 重启 Hub 后仓库仍存在。
- [ ] 点击仓库可启动正确的 Obsidian 仓库。
- [ ] 无效路径不会调用 URI。
- [ ] 单元测试、类型检查、Lint 和 Debug 构建通过。

## M2：完整 MVP

目标：补齐高频使用体验和完整异常状态。

- [ ] 实现无搜索结果状态。
- [ ] 实现收藏与取消收藏。
- [ ] 实现“收藏优先、最近打开其次”的稳定排序。
- [ ] 路径失效时在卡片中展示状态与修复入口。
- [ ] 同名仓库始终显示路径以消除歧义。

### 管理能力

- [ ] 编辑名称、路径和描述。
- [ ] 编辑路径时重新执行完整校验。
- [ ] 实现“从 Hub 移除”确认对话框。
- [ ] 明确说明移除不会删除仓库文件。
- [ ] 处理编辑后与已有路径重复的情况。

### 键盘与无障碍

- [ ] 启动后自动聚焦搜索框。
- [ ] 实现上下方向键移动选择。
- [ ] 实现回车打开当前选择。
- [ ] 实现 `/`、`Ctrl+K`、`Ctrl+N`、`Ctrl+,` 和 `Escape`。
- [ ] 为按钮、输入框、列表和对话框提供可访问名称与语义。
- [ ] 确保焦点态在深浅主题下清晰可见。
- [ ] 检查键盘焦点不会陷入或丢失。

### 视觉系统

- [ ] 建立独立设计令牌和深浅主题。
- [ ] 支持跟随系统主题。
- [ ] 建立紧凑仓库卡片、按钮、输入框、菜单和对话框样式。
- [ ] 不依赖 Obsidian 安装文件、内部 CSS 或商标素材。
- [ ] 检查 100%、125%、150% Windows 缩放。
- [ ] 若已引入 StyleSeed，执行 `/ss-review` 并处理问题。

### 设置与反馈

- [ ] 支持主题模式设置。
- [ ] 支持启动成功后关闭窗口设置。
- [ ] 展示 Obsidian URI 不可用的引导。
