# 跨仓库链接

Bridge 使用仓库前缀加原生形态双链表达跨仓库链接：

显示规则与 Obsidian 原生双链保持一致：阅读模式和光标离开链接时只显示别名或文件名，不显示仓库前缀、路径、箭头或额外下划线；悬停时仍可查看目标仓库和路径。光标进入链接范围后恢复完整源码，便于直接编辑。

```md
@仓库名称[[目录/笔记]]
@仓库名称[[目录/笔记|显示名称]]
```

仓库名和路径可包含中文与空格，路径使用 `/`，序列化时省略 `.md`。解析器预留
`#标题` 和 `^块标识`，当前只保证普通笔记链接的完整交互。

在行首或空白后输入 `@`，Bridge 先显示 Hub 管理的其他仓库。选择仓库后进入临时输入态
`@仓库名称/`，并立即在同一个候选框中显示根目录的文件夹和 Markdown 文件。选择文件夹后
逐级进入下层目录，候选列表可返回上一级；输入文字时，在当前目录树内递归匹配文件名、标题、
别名和相对路径。结果较多时可继续“加载更多”，不再固定截断为首批文件。选择笔记后，如果
Markdown 文件名与标题相同则省略别名，否则以标题作为
别名。选择笔记时 Bridge 一次性写入最终的 `@仓库[[笔记]]`。用户无需手动输入 `[[`；普通
`[[笔记]]` 完全由 Obsidian 处理，Bridge 不再拦截普通方括号输入。

中文输入法下的全角 `＠仓库【【笔记】】` 也能解析；通过补全面板选择时统一写成半角
`@仓库[[笔记]]`。旧三括号语法不再解析、渲染或提供输入补全。

点击已有跨仓库链接时，Bridge 默认从本地磁盘只读加载目标 Markdown，并在当前 Obsidian
窗口打开预览浮窗；浮窗一次只保留一篇正文，不创建或修改任何仓库文件。需要编辑时可点击
“在目标仓库打开”。目标文件缺失或无法读取时显示错误提示，不自动切换仓库。当前不保证
跨仓库附件和嵌入资源完整渲染，也不提供反向链接面板或笔记移动后的自动修复。
